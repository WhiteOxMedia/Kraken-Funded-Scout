-- VERDICT --
Does a flipped state stop losing? The machinery is built so it
must, and the replay shows the arc: the bench requires 3
consecutive fit-losing weeks AND a negative pooled fit edge; the
flipped weeks are then graded live-quantile vs counterfactual-fit
on the same candidate stream, so 'stopped losing' is directly
observable in $/fire; and the fit returns only after consecutive
counterfactual winning weeks AND a positive pooled edge — the
replay shows the pool guard holding the re-arm two extra weeks
(W44) until the recovery out-earned the bad weeks' pooled memory —
the flip-back landed at W45, the first week the pool crossed zero.
The trail now carries ALL FOUR arcs: arc 1 (OUT) where the bench
PAID, arc 2 (RISING) where the bench COST, arc 3 (FLAT) where
the re-arm itself COSTS — there the fit re-armed fast, bled
again, and the gate re-flipped it at the first legal pass the
second bleed allowed, so a wrong re-arm does not linger either.
Arc 2's flip-back re-armed at the first contract-legal pass, so
the wrong bench ended as soon as the contract allows.
Both horizons run on the canonical fit−quantile axis, regime-
normalized by each week's other_src (the pre-fix code would have
re-armed a losing fit — section C shows it firing on raw deltas
the shipped code correctly reads as losing; the shipped rule
cannot). Two honest caveats: (1) the decision metric is $/fire —
per-dollar efficiency — while raw totals can still favor the
benched fit's fatter fire count, which is the ladder-vs-selection
tension, not a bug; (2) one real week of history exists (W37), so
every flip decision above is a seeded replay, not a lived event —
from W38 on this grade is re-runnable from the live ledger.
